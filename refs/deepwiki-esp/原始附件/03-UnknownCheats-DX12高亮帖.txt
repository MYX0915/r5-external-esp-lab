Arrow [DX12] Apex Legends Highlight System - Structure Analysis & Glow Activation

I recently came back to this game after a long break and struggled quite
a bit with getting glow ESP working again, so I wanted to share my
analysis results and the method that finally worked.

Hope this helps someone 

1. OVERVIEW

The DX12 build resolves highlight styles through a global table
(HighlightSettings, RVA 0x6015A70). The table is a continuous array
of 0x34-byte records. The renderer reads a style selector byte at
entity +0x294 and indexes the table as selector * 0x34. A bitmask at
+0x29D marks which of the 4 context slots (+0x295..+0x298) are
focused, and toggling the fade parity at +0x2A8 makes the client
consume the change.

Table extent:
- Tested table count: 128 rows
- Total style storage: 128 * 0x34 = 0x1A00 bytes
- The live count is consumed from the HighlightSettings header at
+0x18.

2. HighlightStyle (stride 0x34)

Code:
struct HighlightStyle       // stride 0x34
{
    std::uint32_t functionBits;  // +0x00  mode bits, read as dword
    float         colorR;        // +0x04
    float         colorG;        // +0x08
    float         colorB;        // +0x0C
    float         parameter10;   // +0x10
    float         parameter14;   // +0x14
    float         parameter18;   // +0x18
    float         parameter1C;   // +0x1C
    float         maxDistance;   // +0x20
    std::uint32_t field24;       // +0x24
    std::uint32_t field28;       // +0x28
    std::uint32_t field2C;       // +0x2C
    std::int32_t  field30;       // +0x30  NOT a row index
};
static_assert(sizeof(HighlightStyle) == 0x34);
Notes:
- +0x00 is a dword of mode bits, not a float.
- No RGBA array exists in this structure. Only RGB is confirmed at
+0x04 / +0x08 / +0x0C. Do not claim an alpha channel.
- +0x10..+0x1C are unconfirmed parameters - keep them from a
verified row instead of guessing semantics.
- +0x30 is NOT a row index.

Stride warning: parsing this continuous table at 0x40-byte boundaries
makes each displayed row drift by +0x0C relative to the real 0x34-byte
records. Always use stride 0x34.

3. Entity Highlight Fields

Code:
  +0x294            uint8  style selector      // renderer reads THIS
  +0x295..+0x298    uint8  genericContexts[4]
  +0x299..+0x29C    unknown - do not touch
  +0x29D            uint8  focusedMask         // bit0 = context slot 0
  +0x2A0                  fade-duration state (exact sub-layout not
                          established)
  +0x2A8            uint32 m_highlightFadeParity // toggle on change
IMPORTANT:
- The renderer reads +0x294, not +0x295. Writing only +0x295 never
selects a row - this was why modified rows were never rendered.
- genericContexts[0] is NOT always a mirror of the selector. In the
resting state they can hold different values. During activation we
set them to the same row so focused slot 0 resolves correctly.
- focusedMask is a bitmask with one bit per context slot, NOT a
boolean. To activate slot 0: value |= 1.
- Use uint8_t for the selector/context values. 0xFF is confirmed as
the invalid selector value at +0x294. Context slots also commonly
contain 0xFF as an unused value.
- +0x299..+0x29C are unverified. Do not write.

4. Activation Sequence

Perform the selector/context/focus writes as one tightly grouped
update, then toggle fadeParity last as the change notification.
(External writes - there is no same-frame guarantee.)

Code:
  Step 1: entity +0x294 = row      // selector the renderer uses
  Step 2: entity +0x295 = row      // contexts[0], so slot 0 is focused
  Step 3: entity +0x29D |= 1       // focus slot 0 (bitmask)
  Step 4: entity +0x2A8 ^= 1       // notify change
5. Activation Procedure

5a. Resolve the table

Code:
  uintptr_t settings;
  Read(moduleBase + 0x6015A70, &settings, 8);
  // 0x6015830 is null/stale in this build - do not use it.
5b. Prepare a style row

Option A (preferred) - patch a verified native row:
Rows 50 (visible) and 2 (occluded) are native rows verified to render.
Patching them changes those styles globally for every system that
selects them, so always save the complete 0x34 rows and restore them
on disable. Modify ONLY the RGB fields - keep functionBits and all
parameters untouched.

Code:
  Read(settings + 50 * 0x34, &row50, 0x34);
  row50.colorR = 1.0f;  row50.colorG = 0.10f; row50.colorB = 0.10f;
  Write(settings + 50 * 0x34, &row50, 0x34);
Option B - clone into a zeroed row:
Search only within the live row count (128). A zero row is not
guaranteed to remain unused, so save it, revalidate it before use,
and restore it on disable. Clone a verified template row into it,
then patch only RGB.

5c. Apply to entity

Code:
  uint8_t  row = chosenRow;      // e.g. 50 (visible) or 2 (occluded)
  uint8_t  focused;
  uint32_t parity;
 
  Read(entity + 0x29D, &focused, 1);
  Read(entity + 0x2A8, &parity, 4);
 
  Write(entity + 0x294, &row, 1);      // selector (renderer reads this)
  Write(entity + 0x295, &row, 1);      // contexts[0]
  focused |= 1;                         // bit 0 = slot 0
  Write(entity + 0x29D, &focused, 1);
  parity ^= 1;
  Write(entity + 0x2A8, &parity, 4);
5d. Restore on disable

Save each written field individually before first write, and restore
them individually - do not save a flat byte range:

Code:
  uint8_t  originalSelector;   // +0x294
  uint8_t  originalContext0;   // +0x295
  uint8_t  originalFocused;    // +0x29D
  uint32_t originalParity;     // +0x2A8
Also restore the borrowed style row(s) to their original 0x34 bytes.

6. Common Pitfalls

- Writing +0x295 without +0x294: the row is never selected, nothing
renders.
- Stride must be 0x34. 0x40-byte parsing drifts by 0x0C per row.
- Global RVA is 0x6015A70 in this build (0x6015830 reads null).
- focusedMask: use |= 1. Writing 1 wholesale clears the bits of the
other slots.
- Do not touch +0x299..+0x29C.
- Parity must be toggled, never set to a constant.
- 0xFF means invalid at +0x294; context slots use it as unused.
- Do not assume rows 64..127 are free. Used rows exist past 64.

7. Memory Layout Reference

Code:
HighlightStyle (stride 0x34):
 
  +0x00  uint32  functionBits (mode)
  +0x04  float   color R
  +0x08  float   color G
  +0x0C  float   color B
  +0x10  float   parameter10
  +0x14  float   parameter14
  +0x18  float   parameter18
  +0x1C  float   parameter1C
  +0x20  float   maxDistance
  +0x24  uint32  field24
  +0x28  uint32  field28
  +0x2C  uint32  field2C
  +0x30  int32   field30 (not index)
 
Entity highlight fields:
 
  +0x294      uint8   style selector (renderer)
  +0x295      uint8   genericContexts[0]
  +0x296-298  uint8   genericContexts[1..3]
  +0x299-29C          unknown - do not touch
  +0x29D      uint8   focusedMask (|=1 for slot 0)
  +0x2A0              fade-duration state (layout not established)
  +0x2A8      uint32  fadeParity (^=1)
 
Global:
 
  HighlightSettings  = 0x6015A70
