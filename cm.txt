静态分析完成：高亮系统的完整判定链与写入方案

子代理分析 44.6MB .text dump，产出 559 行报告
（refs/highlight-static-analysis.md + inject-kit/analysis/sa_*.py）

三个关键更正:
1. 0x72BE6C0 是全局结构体而非数组本体
   +0x00 = 堆上条目数组指针（活体 0x131D12F00）
   +0x18 = 条目数（活体 90，容量 128）
   条目地址 = (*(u64*)0x72BE6C0) + id*0x34，静态不可知
   全 .text 仅 8 处 imul,0x34 真接到它（此前"12 处"属误计）

2. Highlight_Enable (0x202D780) 是查询不是开关
   只读 [entity+0x33C] bit1，压 VM 值栈，return 1
   零写入、零虚调用；0x2800... 是 VM 值类型标签（>>59=5）

3. 颜色真正来源
   构建器 0x2017E50 从 (*(u64*)0x72BE6C0)+id*0x34 读
   +0x04..0x0C（外轮廓 RGB）与 +0x10..0x18（内部 RGB）
   可被实体覆盖:
     +0x2BC 字节 ≠0 → 启用 outline 覆盖
     +0x2C0/0x2C4/0x2C8 float×3 = outline 覆盖 RGB
     +0x2BD 字节 ≠0 → 启用 inside 覆盖（全 .text 无写者，静态稳定）
     +0x2CC/0x2D0/0x2D4 float×3 = inside 覆盖 RGB

完整闸门链（任一不满足即丢弃）:
  闸门1 [entity+0x33C] & 2
  闸门2 [entity+0x298] 为有效指针且 *ptr != 0xFF
  闸门3 两组颜色不全为 0
  闸门4 淡入曲线 0x2017C60 非 0（依赖 +0x19C）

运行时实测:
  我们 64 个实体的 +0x298 全是 0x29E1_002A_xxxx
  （高16恒定、serial=0x2A、低16变化 0x9F37~0xA2AA）
  探测该值 → 0x8000000D 未映射 → 不是指针
  → 闸门2 无法满足
